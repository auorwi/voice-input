# 自动输入目标识别（1.1.66）

录音开始时通过 macOS NSWorkspace 读取实时前台进程和 bundle ID，再捕获该进程的输入焦点。用于润色的应用上下文仍由后台缓存提供，但缓存不再决定键盘输出目标。读取失败时不复用上一个应用。实时目标查询不运行浏览器 AppleScript，也不新增系统权限。

优先读取 AXFocusedUIElement。若系统暂时只返回窗口或容器，则读取当前聚焦窗口的结构节点，再检查直接焦点。只有一个明确标记为聚焦、启用、可编辑的文本控件，且窗口未变化、读取完整时，才可作为后备目标。明确的按钮、密码框、只读字段焦点不会被旁边的文本框替代。

后备读取最多两轮、96 个节点、12 层，只展开结构容器，不展开消息列表、表格、树列表或文档内容；不读取聊天正文。400 ms 为查询预算，每次原生 AX 消息另设 50 ms 超时，同步系统调用可能使实际耗时略超预算。读取出错、多个候选、窗口变化或预算用尽时保留结果弹窗，避免写错地方。

录音开始、输出前以及写入后检查共用焦点解析。输出前仍比较应用进程和控件标识。没有添加应用白名单或向未知控件盲目粘贴。

1.1.66 修复“浏览器已经输入却仍弹出复制框”：1.1.64 的机制只忽略不可回读，仍会把可读取但不一致的 AX 文字当作失败。网页编辑器的回读可能延迟、规范化换行或仅提供局部范围，不能可靠否定成功发送。现在 `decide_after_output` 以发送状态为准：`Inserted` 不弹窗；`Failed`、`PartiallyInserted`、`CopiedFallback` 均保留完整结果供编辑复制。回读只用于本机诊断，不会触发重发，也不新增文字日志或外发。

此策略优先避免成功输入后的干扰，不保证每个编辑器实际接收了全部按键：系统报告成功但目标静默丢弃输入时，不自动弹窗，可从历史记录找回文字。输出前目标缺失、变化、密码框、只读字段和无法确认身份的保护仍然保留。

回归覆盖成功发送后回读旧文字、附加换行、截断范围，以及三种发送失败状态与全部回读结果的组合。既有覆盖包括快速切换应用、实时目标消失、目标查询绕过上下文补全、窗口暂时代替焦点、迟到焦点、搜索框和聊天框并存、多个焦点、窗口切换、密码/只读/按钮、读取失败、循环和遍历预算。

模拟测试验证判定规则，并不能证明所有版本微信和浏览器都及时提供辅助功能信息；真实语音录入仍需在安装版和实际输入框中验证。此次回归仅用本地测试，不调用语音识别或 DeepSeek 服务。
